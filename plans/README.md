## Direction findings deferred (not planned this run)

- **Worktree visibility / manual cleanup**: every send attempt creates a
  detached worktree under `~/.codex/worktrees/<short-id>/<repo-name>` and
  nothing ever deletes them (by MVP design — `docs/operator-descktop-mvp.md`
  forbids automatic cleanup). A Settings surface listing Operator-created
  worktrees with a manual prune action is a good M-effort follow-up once
  dogfooding accumulates enough clutter to hurt. Deliberately deferred:
  deleting user work is the riskiest feature in the app; design it after 003
  settles whether old worktrees can still receive follow-up turns.
- **Model selection**: the model is hardcoded as `gpt-5.5`
  (`codex_operator/Sources/OperatorDesktop/Repositories/CodexTriggerService.swift:130`).
  The app-server request already carries `model` as a parameter, so a picker
  is S effort — but it was explicitly excluded from the MVP to avoid
  distraction, and nothing in dogfooding evidence yet demands it. Revisit
  when a second model is actually wanted.
- **Decide the webapp's fate**: `webapp/` is an experimental Cursor-SDK app
  whose direction the desktop MVP PRD "deliberately supersedes"
  (`docs/operator-descktop-mvp.md:236`), yet it still carries a
  `ready-for-agent` PRD (`.scratch/add-project-ux/PRD.md`) and live
  dependencies. This is a maintainer decision, not a plan: either archive it
  (mark the add-project-ux PRD `wontfix`, freeze the directory) or restate
  its purpose in the root README. Until decided, agents may waste effort
  implementing webapp PRDs that no longer matter.
